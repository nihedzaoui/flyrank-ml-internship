Abstract

This study asks whether observable content-performance signals can help rank pages for refresh review more effectively than a transparent rule-based queue. The reproducible public release contains 30,000 pseudonymized content items and 44 columns, while the internship workflow is designed to scale to a larger hosted release without publishing private production data. Decline is defined from the observed trend_direction field, which is excluded from the model together with trend_pct, identifiers, and other target-derived variables. A Random Forest evaluated with a client-holdout split achieved Precision@50 = 0.740 versus 0.240 for the rule baseline, with ROC-AUC of 0.750 versus 0.627. The resulting score is decision support for human review, not evidence that refreshing a page will cause future search performance to improve.

1. Introduction / Problem

The practical question is not which pages are universally “bad”. It is which existing pages should an editor inspect first when review capacity is limited.

Each row represents one pseudonymized content item. The system outputs a ranked review queue; a human then checks the page, its editorial context, and the evidence behind the recommendation before any change is made.

Research question. Can a leakage-safe machine-learning ranking concentrate observed decline cases near the top of the review queue more effectively than a transparent rule?

3. Methodology

Validation design

A GroupShuffleSplit holds out approximately 20% of clients, preventing pages from the same client from appearing in both train and test. The reference notebook used 25 training clients and 7 test clients, with no client overlap.

Model

A Random Forest classifier converts the positive-class probability into a ranking score. Numeric features use median imputation; categorical features use most-frequent imputation and one-hot encoding. The reported configuration uses 300 trees, maximum depth 12, minimum leaf size 5, balanced class weights, and random seed 42.

Leakage audit

The audit explicitly excludes outcome-derived trend fields. This is essential because the target itself is defined from trend_direction.

5. Limitations & honest framing

  1. The label is a proxy derived from observed trend information, not a direct measure of editorial quality.
  2. The data is observational; the analysis does not establish that refreshing a page causes future performance to improve.
  3. The public artifact reports the reproducible 30,000-row release rather than unpublished production rows.
  4. Client-grouped validation is stricter than random row splitting when client-specific patterns exist.
  5. Model scores are ranking signals, not calibrated business-outcome probabilities.
  6. No recommendation automatically publishes, refreshes, redirects, or rewrites content.

Interpretation: the model ranks pages that look worth reviewing first, given the observed signals and this validation design.

6. Ranked recommendations

  1. Review high-confidence candidates first. Verify the page and editorial context.
  2. Check the visible opportunity. Use impressions, CTR, engagement, position, and freshness as evidence.
  3. Separate CTR and engagement diagnoses. Inspect the evidence behind the review reason before selecting an intervention.
  4. Keep a human approval gate. Treat the output as a review queue rather than an automatic publishing decision.
  5. Monitor prospectively. If refreshes occur, collect pre/post outcomes and use an appropriate time-aware or experimental design before causal claims.
